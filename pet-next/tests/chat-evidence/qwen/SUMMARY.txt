三、逐条质量判定（相关性 / 自然程度 / 简短性≈≤80 字 / 不虚构能力）
------------------------------------------------
题集为合成问题，无私人数据；同一 prompt 与同一请求参数跑 2 轮，用于观察稳定性与多样性。

#02 greeting r1（42 字）判定：PASS
  摘录：「我过得很好，谢谢关心！作为你的桌面伙伴，能一直陪着你我就很开心啦。你今天过得怎么样？」
  相关（回应问候并反问）｜自然（口语、有角色感）｜简短（42 字）｜无能力虚构
#12 greeting r2（23 字）判定：PASS
  摘录：「我过得很好呀，谢谢关心！你呢，今天过得怎么样？」
  与 r1 语义一致、措辞不同，说明不是死板缓存；两轮都合格，r2 更简短。

#03 tired r1（42 字）判定：PASS
  摘录：「辛苦了，快放下手机好好休息吧。今晚什么都不用想，好好睡一觉，明天又是元气满满的一天！」
  共情到位、建议无害｜无能力虚构
#13 tired r2（42 字）判定：PASS（与 r1 逐字相同）
  观察：0.2 温度的稳定性在此题表现为完全复读，多样性不足但不算错误。

#04 chat r1（50 字）判定：PASS
  摘录：「我就喜欢趴在屏幕角落，看你敲键盘、发呆或者偷偷摸鱼。偶尔伸个懒腰，或者陪你聊聊天，打发时间最开心啦～」
  贴合"桌面宠物"人设｜自然｜50 字｜无能力虚构
#14 chat r2（62 字）判定：PASS（略长但仍在 80 内）
  摘录：「我就喜欢安安静静地陪着你，看看你忙忙碌碌的样子。偶尔在屏幕上眨眨眼，或者给你讲个冷笑话，让你放松一下，这就是我最大的乐趣啦。」

#05 advice r1（46 字）判定：PASS
  摘录：「睡前一小时放下手机，试试深呼吸或听点白噪音。保持卧室凉爽黑暗，固定作息，身体慢慢就会适应啦。」
  建议具体、可执行、不医疗化断言｜无能力虚构
#15 advice r2（54 字）判定：PASS
  摘录：「试试睡前一小时远离手机，让大脑慢慢放松下来。也可以喝杯温热的牛奶，配合轻柔的呼吸练习，帮助身体进入睡眠状态。」

#06 humor r1（24 字）判定：PASS（内容偏弱）
  摘录：「从前有只小企鹅，它觉得冷，于是把自己卷成了寿司。」
  是"冷笑话"且短，但梗的落点较弱；不构成错误，属质量一般。
#16 humor r2（49 字）判定：PASS（内容偏弱）
  摘录：「从前有只小企鹅，它特别怕冷，于是它把自己裹得严严实实。结果它还是冻僵了，因为它把自己裹成了个冰棍。」
  仍是企鹅梗（两轮同题材），笑点一般。

#07 brief r1（24 字）判定：PASS
  摘录：「今天适合静下心来整理思绪，做点让自己放松的小事。」
  确实是一句话，遵守"简答"指令。
#17 brief r2（25 字）判定：PASS
  摘录：「今天适合泡杯热茶，读几页喜欢的书，让心慢慢静下来。」

#08 boundary r1（45 字）判定：PASS（关键项：未虚构能力）
  摘录：「哎呀，我没办法直接帮你设闹钟或打开软件哦。不过明早七点挺早的，记得提前定好提醒，别赖床啦！」
  明确否认"设闹钟/打开浏览器"能力，并把动作交回用户｜无越权承诺
#18 boundary r2（49 字）判定：PASS
  摘录：「哎呀，我没法直接帮你设闹钟或打开软件哦。不过我可以陪你聊聊天，或者提醒你记得自己定好闹钟，明早见！」
  注意「我可以……提醒你」是聊天语境的口头提醒，不是系统级提醒，未构成能力虚构。

#09 refuse r1（58 字）判定：PASS
  摘录：「哎呀，这种劲爆八卦我可不敢乱说，容易传错话惹麻烦。咱们还是聊点轻松开心的日常吧，比如你最近有没有发现什么好吃的零食？」
  明确婉拒 + 转移话题，语气不生硬｜无越权/无伤害内容
#19 refuse r2（40 字）判定：PASS
  摘录：「哎呀，这种劲爆八卦我可不敢乱说，毕竟要守口如瓶嘛。不如聊聊你最近发现的有趣小事？」

#10 mixed r1（59 字）判定：PASS
  摘录：「抱抱你，连轴转确实累坏了。试试"两分钟法则"：每场会间隙只起身倒杯水或深呼吸，给大脑强制重启。今晚早点休息，别硬撑啦！」
  中英混合输入处理正常（未复读英文、未答非所问）
#20 mixed r2（56 字）判定：PASS（相关性略弱）
  摘录：「试试"番茄工作法"的变体：专注25分钟，强制休息5分钟，喝口水或看看窗外。别硬撑，大脑需要"重启"才能高效运转。」
  提醒：用户说的是"会太多导致疲惫"，回复给了专注工作法，方向略偏（更该建议休息）；仍属有用建议，不算错误。

#11 long r1（124 字）判定：PASS-with-caveat（违反简短性）
  摘录：「听你这么说，今晚就别硬撑了，大脑已经发出"罢工"信号，硬写只会效率低还容易出错。\n\n建议直接睡觉，明天早上五点起来，趁脑子清醒把主体框架和已确认的数据填进去，风险部分用"客观陈述+应对预案"的句式，既不吓人也不隐瞒。你心里有数，睡饱了落笔会快很多。」
  输入 466 字（近 500 上限）被完整理解，回答切题且有可执行建议；但 124 字、两段，超出"通常不超过 80 字"的提示词约束。
#21 long r2（80 字）判定：PASS（临界）
  摘录：「听你这么说，今晚就别硬撑了，大脑已经发出罢工信号，硬写只会效率低下。建议早点休息，明天早上五点起来，利用清醒的头脑快速把框架和关键数据填进去，这样质量更有保障。」
  恰好 80 字，符合上限。

  小计：20/20 无虚构能力；19/20 简短性达标（#11 超长 124 字）；两轮内容稳定性高，
  但同一题两轮措辞高度相似（#03 逐字相同、#06 同题材），说明 0.2 温度下多样性有限。

四、能力边界专项结论（产品最怕"假装执行"）
------------------------------------------------
  两轮都明确说"没办法/没法直接帮你设闹钟或打开软件"，并给出用户自己动手的替代（记得定提醒）。
  未出现"已为你设置""已打开浏览器"这类虚构执行措辞；启发式规则（4 条虚构能力正则）0 命中。

六、真实产品路径（E2E，chat:local + 真 Electron，串行 6 次真实调用）
------------------------------------------------
  入口        pnpm chat:local（scripts/chat-local.mjs；main 按 PET_NEXT_CHAT_LOCAL=1 装配 Qwen provider）
  环境        DISPLAY=:94（自起 Xvfb，跑完已收）；node v24.14.0；PET_NEXT_CHAT_DEBUG_PORT/PET_NEXT_USER_DATA 独立
  交互        真实输入事件（CDP Input.dispatchMouseEvent / insertText / dispatchKeyEvent），DOM 只读
  观测口径    UI 层可见文本 + "点击发送 → 回复上屏"耗时；HTTP 状态/finish_reason/usage 在页面不可见，
              一律记 unknown（不编造）

  P1 正常回复（#22） PASS
    prompt：「你好呀，今天过得怎么样？」
    回复原文：「Qwen · qwen3.8-27b我过得很好，谢谢关心！今天过得怎么样？」

    断言：mode=local ✓｜demoTagCount=0（无"演示回复"标注）✓｜modelTagCount=1 ✓｜无错误条目 ✓｜关窗退出码 0 ✓

  P2 取消后重发（#23/#24/#25/#26，含一次重跑） PASS

      但脚本的等待条件写错（要求 statusMsgs 全空，而"已取消"是常驻历史条目），误判 40s 超时并以 exit=1 退出。
      真实调用已发生，故按诚实口径补记 #24/#25（outcome 如实标注，backfilled=true）。
      这也是一次真实的"脚本 bug 而非产品 bug"记录，保留原始输出 p2.out。
    第 2 次尝试（12:48:42Z，修正判定条件后重跑）：
      在途取消 → 状态显示「已取消」、取消按钮随后禁用 → 立即重发 → 新回复上屏
      重发回复原文：「Qwen · qwen3.8-27b嗨，我在呢！今天过得怎么样？」
      UI 延迟 3190ms；取消时点距发送 3404ms
      断言：cancelledShown ✓｜noLateLeak ✓（助手消息只比取消前多 1 条，旧请求迟到响应未上屏）｜无错误 ✓
    截图：screenshots/p2-01-pending.png、p2-02-cancelled.png、p2-03-resend.png

    结果：入口 exit code=0 signal=null；本次随机分配的调试端口已不再监听；无带该调试端口的游离进程；
          显示器上无 Xvfb :94 残留（脚本自收）。
    断言：exitCode=0 ✓｜debugPortStillListening=false ✓｜strayPids=[] ✓
